# 讨论工作流

## 从当前位置开始

用 `treecer context show --json` 或 MCP context 读取当前绑定、位置、正文、祖先和直接孩子。核对对象后再接续。

首次进入项目会看到任务目录。已有工作用 task use 或 MCP use_task 按名称选择；新工作用 task add 或 MCP tasks(title=...) 创建。`~` 是该任务的讨论根，各个主题作为其孩子。

## 记录结论和问题

正文按实际需要组织，例如：

```text
问题与目的：怎样让助手恢复刚才讨论的位置？
用户已确定：项目与任务分开，会话位置持久保存。
助手建议：按来源与会话保存位置。
待讨论：接入端怎样提供稳定会话标识？
下一步：走通一次客户端重启。
```

区分用户决定、助手建议和未决问题。部分结论已确定时，保留剩余缺口。正文材料不足时注明需要补齐的事实。

## 分叉和暂放

node add 或 MCP add_node 在当前节点下新增问题，也可用 parent 指定父路径。工具返回新路径，同时保留原位置。转入新问题时调用 focus。

暂时不聊的旁枝记录问题和返回条件，状态设为「暂放」。同一父节点下名称唯一，跨分支同名时用完整路径区分。

## 收束与回溯

先读取，使用返回的 revision 更新。例如实际读取值为 4：

```text
treecer node get "~/方案讨论/方案比较" --json
treecer node update "~/方案讨论/方案比较" --revision 4 --status 已解决 --note "用户已确定：……"
treecer parent
treecer focus ..
treecer children
```

核对当前节点解决了父问题的哪部分，再回到父问题，选择未完成的兄弟分支。父节点状态由明确更新决定。用户可随时改变讨论顺序。

重新开放的问题恢复为「讨论中」。新决定替代旧提议时更新有效结论，并保留必要的取舍原因。

## 跨任务查阅与协作

查看其他任务时用 `/项目/任务/节点`。读取保留当前任务和位置；返回对象附有准确路径。若用户确实需要修改其他任务，核对警告中的目标后，在该次写请求显式提供 sudo。

更新遇到 REVISION_CONFLICT 时，合并 current 中最新且仍有效的内容后，用新的 revision 提交。改名或移动后沿用返回的新路径，保存的会话位置通过内部身份跟随。

每个聊天保持稳定 source/session；多来源内容共享、位置独立。孩子或搜索返回 next_offset 时，可以按需继续读取后续页。

重要结论、分叉、转向或一轮讨论结束时维护记录，交谈以实质问题为主。讨论记录沿用当前任务授权，代码实施、架构意图修改、部署与外部操作按各自任务授权执行。
