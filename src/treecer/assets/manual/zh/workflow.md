# 讨论工作流

## 从当前位置开始

先调用 `treecer context show --json`，或 MCP 的 `context`，查看项目、任务、祖先路径、当前正文和直接孩子。核对讨论对象，按需要回查祖先节点。

新会话先看项目概览。用户提到已有任务时，查找并选择该任务；开始新工作时创建任务。项目级树可以记录暂未归入任务的问题。

## 记录有用的问题与结论

把值得继续讨论的问题保存为节点，保留目的和必要上下文。例如正文可以写：

```text
问题与目的：怎样让助手恢复刚才讨论的位置？
用户已确定：项目与任务分开，会话位置持久保存。
助手建议：来源和会话共同标识接续位置。
待讨论：接入端怎样提供稳定会话标识？
下一步：走通一次客户端重启。
```

按实际需要保留栏目。用户决定、助手提议和未决问题分别表述；材料缺失时记录缺口。部分结论已定时，保留尚未解决的问题。

## 深入与暂放

出现值得深入的新问题，用 `node add` 或 MCP `add_node` 创建孩子，获得自动 ID。添加节点保持原位置；实际转入该问题时调用 `focus`。

旁枝暂时不聊时记录一句问题、关联背景及返回条件，将状态设为「暂放」，继续原讨论。标题相同时依靠 ID 和路径区分。

## 收束与回溯

当前问题聊完后，更新结论，核对它解决了父问题的哪一部分：

```text
treecer node get N27 --json
treecer node update N27 --revision 3 --status 已解决 --note "用户已确定：……"
treecer parent
treecer focus ..
treecer children
```

示例 ID 与修订号以实际读取结果为准。`parent` 读取父节点和路径，`focus ..` 保存返回父问题后的位置。再看父问题仍缺什么，选择开放的兄弟分支。用户可以随时改变顺序。

重新开放问题时恢复「讨论中」。旧建议被新决定替代时更新有效结论，并按需要保留取舍原因。

## 更新与协作

重要结论、分叉、转向或一轮讨论结束时更新即可。日常对话以问题本身为主。

读取后使用返回的 `revision` 更新。遇到 `REVISION_CONFLICT`，根据返回的最新内容合并仍然有效的双方信息，再提交。不同会话的焦点独立，讨论内容共享。

使用同一来源和稳定会话标识接续；换聊天后也可以通过任务和树重新定位。孩子分页有 `next_offset` 时，可按需要继续读取。

讨论记录沿用当前任务授权。源码实施、架构意图修改、部署和外部操作按各自任务授权推进。
