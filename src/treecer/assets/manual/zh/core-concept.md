# 核心概念

## 项目、任务、树与节点

- 项目表示独立工作空间，例如 Project 和一个游戏项目。每个项目拥有独立数据库，稳定项目 ID 与显示名称分开。
- 任务表示项目内持续推进的一项工作，例如记忆系统设计。同一任务可以经过多个聊天和助手接续。
- 讨论树归属项目，可以关联某项任务；任务为空时为项目级树。一个任务允许多棵树。
- 节点保存一个问题、标题、正文、状态和父子关系。一棵树只有一个根节点，父子关系保持同树和无环。

项目级树可以先容纳尚未形成明确任务的灵感。助手根据用户表达选择或创建任务；新会话先看项目概览。

## 身份与名称

项目 ID 自动生成。任务 ID 为 `T…`，树 ID 为 `R…`，节点 ID 为 `N…`，都由工具分配。同一项目内节点 ID 唯一；不同项目可以有相同节点编号，完整定位依赖项目归属。

节点标题允许重复，改名和移动保留 ID。按标题查找返回每项的 ID 和祖先路径，操作使用选定的 ID。同名任务需要用任务 ID 区分。

## 位置提示

```text
Topic@Project# 方案讨论/方案比较/比较标准 [N27]
```

`Topic` 为任务，`Project` 为项目，后半段为根到当前节点的路径。没有选中任务时显示 `~`；没有选中节点时显示 `/`。

工具从当前节点沿父节点回溯，生成最新路径。标题中的 `/`、`%` 和换行在提示中转义，JSON 路径数组保留原始标题及每段 ID。

## 内容、状态与修订号

节点正文 `note` 使用 Markdown，按需要记录问题目的、用户已确定、助手建议、待讨论和下一步。

状态为「讨论中、已解决、暂放、已取消」。一个讨论中的节点可以含有部分已确定结论；父节点状态由明确更新决定。暂放节点仍可见，可记录返回条件。

`revision` 是节点修订号。读取返回当前值，更新和移动携带所依据的值。其他调用已经修改节点时返回冲突及最新内容，让助手合并后提交。

## 来源、会话与接续位置

来源标识接入入口，如 codex 或另一个助手。会话标识该来源下的具体聊天。来源与会话共同确定项目绑定，以及项目内的任务、树和节点位置。

多个会话可以访问同一棵树并保留各自位置。读取和添加孩子保持当前位置；`focus` 更新位置。CLI 默认按工作区接续；独立聊天可提供 `--source` 和 `--session`。MCP 用 `scope.source`、`scope.session` 传递身份。

## 项目发现与存储

CLI 以实际工作目录或 `--workspace` 定位；MCP 以启动参数或工具参数提供的工作区定位。工作区标记 `.treecer/project.json` 保存稳定项目 ID，用户数据目录的 `catalog.sqlite` 保存项目及工作区登记；`projects/<项目ID>/project.sqlite` 保存项目内容和位置。

显式项目选择会固定当前会话的项目；清除固定关联后，工具重新根据工作区发现。详细优先级、数据位置和恢复方法见 `treecer doc reference`。
