# 核心概念

## 项目、任务和节点

项目是独立工作空间，例如 Project 和另一个项目；每个项目有独立数据库。任务是项目内可跨聊天接续的一项工作。每项任务拥有一棵根为 ~ 的讨论树，主题和子问题都作为节点保存。

同一项目内任务名称唯一，同一父节点下节点名称唯一；不同分支可以有同名节点。名称按大小写和原字符精确匹配。内部稳定身份维持关系和会话位置，对外操作使用名称和路径。

## 路径空间

| 写法 | 含义 |
| --- | --- |
| / | Treecer 的全局项目目录 |
| /Project | Project 项目的任务目录 |
| /Project/Topic | 指定任务的根 |
| ~ | 当前绑定任务的根 |
| ~/方案讨论 | 从当前任务根定位 |
| 子问题 | 从当前讨论位置定位 |
| . / .. | 当前位置 / 上一级 |

例如 `Topic@Project: ~/方案讨论/方案选择$` 的绝对地址是 `/Project/Topic/方案讨论/方案选择`。$ 是提示符，不是路径内容。

路径分段编码，标题保留原始字符。/ 编码成 %2F，% 编码成 %25，换行编码成 %0A 或 %0D；完整名称为 .、..、~ 时分别编码为 %2E、%2E%2E、%7E。按 / 分段后才解码，因此这些字符仍可作为节点名称。

## 当前任务、位置和操作对象

当前任务是 ~ 的展开依据。当前位置是正在讨论的节点，也可以是项目目录或全局目录。prompt 始终描述当前位置；返回的 target 与 node 描述本次操作对象。

普通读取、新增、更新和移动不会主动切换位置。focus 是明确的导航动作：进入路径或返回父节点。focus 到其他任务时，原任务绑定仍保留，当前位置用绝对路径显示；写该位置仍按跨任务规则检查。task use 明确改变任务绑定，并恢复该任务自己的位置。

改名、移动保留内部节点身份，会话位置跟随节点生成新路径。跨项目移动同样保留身份。助手持有的旧路径需要按新结果更新。

## 内容与修订号

note 使用 Markdown，按需写问题目的、用户已确定、助手建议、待讨论和下一步。状态为「讨论中、已解决、暂放、已取消」，由显式更新决定。

revision 是内容版本。读取后携带它更新或移动；其他调用已经改变节点时，返回 REVISION_CONFLICT 和当前内容。修订号也帮助识别旧路径被另一个节点占用后的过期修改。

## 来源与会话

来源表示接入入口，会话表示其中的具体聊天。同一项目的讨论内容共享，各来源和会话有独立的任务选择和位置。用户切换任务后可以返回原位置。

CLI 默认按工作区接续，可用 --source、--session 或 TREECER_SESSION 区分聊天。MCP 用 scope.source 和 scope.session，未提供稳定标识时服务器生成并返回一个会话标识；跨重启时重新提供它。

## 跨任务操作

读取、列孩子、查路径和搜索可以跨任务执行。修改其他任务的内容或结构时，需要本次请求显式 sudo；未确认时显示当前任务、目标任务、目标路径和修正建议，并保留原数据。

sudo 是 Treecer 内部的一次请求确认，不需要密码。~、相对路径和 .. 先统一解析，再判断最终目标归属。单次覆写保留当前任务绑定，后续请求重新检查。
