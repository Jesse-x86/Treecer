# 用 Treecer 接续讨论

先通过 MCP `context` 或 CLI `treecer context show --json` 读取当前关联。需要接入说明时运行 `treecer setup`，命令语法看 `--help`。CLI 离线手册用 `treecer doc` 列出主题，`treecer doc reference` 查询参数和错误处理；默认中文，`--en` 阅读英文。

## 定位

位置显示为 `任务@项目# 根问题/当前问题 [节点ID]`。核对它与实际讨论对象一致。

工作区通常自动识别。MCP 缺少依据时在 `scope.workspace` 提供实际工作区；用 `scope.source` 和稳定的 `scope.session` 标识当前聊天。返回的 session 可以保存供重启接续。CLI 对应参数为 `--workspace`、`--source`、`--session`。

已有任务按用户表达接续，使用任务 ID 或唯一名称选择；新任务可由助手创建。新会话的项目概览列出任务，任务内 `trees` 返回讨论树。用户没有明确任务时，可以使用项目级树。

## 记录与深入

从实际讨论提取问题与目的、用户已确定、助手建议、待讨论和下一步，按需要写入 note。节点状态为讨论中、已解决、暂放、已取消；部分结论已定但仍有问题时，保留讨论中并记录缺口。

值得深入的新问题建为当前节点的孩子；暂放的旁枝记录问题与返回条件。节点 ID 自动生成，显示标题和 ID，操作使用工具返回的 ID。同名时用路径区分。

重要结论、分叉、转向或一轮讨论结束时更新即可。普通聊天无需逐句建节点，也无需每条回复调用工具。实际切换讨论位置时调用 `focus`；新增孩子和读取节点保持原位置。

更新前读取节点，用返回的 revision 提交。遇到 REVISION_CONFLICT 时读取当前内容，将仍有效的双方结论合并后提交。明确区分用户采纳与助手提议，材料缺失时注明缺口。

## 回溯与接续

日常用 `context` 一次获取祖先路径、当前正文与一层孩子；需要更多内容时按 ID 读取。孩子分页的 next_offset 非空时仍有后续项。

聊完当前节点，记录它解决了父问题的哪部分和剩余缺口，用 `parent` 查询、用 `focus` 回到父节点。选择仍开放的兄弟分支接着讨论。暂放分支保留在可接续路线中，用户可以随时改变顺序。

旧结论被新决定替代时更新有效结论，保留必要取舍原因。重新开放的问题恢复为讨论中。

回答以实质问题为主，需要导航时自然说明当前分支的结论与接下来可讨论的问题。讨论记录沿用用户当前授权；源码实施、意图修改、部署和外部操作按对应任务授权执行。
