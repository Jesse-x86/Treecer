# 用 Treecer 接续讨论

先用 MCP context 或 CLI `treecer context show --json` 查看当前项目、任务和位置。命令参数看 --help；`treecer doc reference` 是离线操作参考，--en 阅读英文。setup 显示接入指南和本 skill 的安装位置。

## 定位

提示为 `任务@项目: ~/主题/当前问题$`。~ 是当前绑定任务的根；绝对地址为 `/项目/任务/节点`。节点按名称和路径操作，内部身份由工具维护。

工作区通常自动识别。MCP 缺少依据时在 scope.workspace 提供实际工作区，用 scope.source 和稳定 scope.session 标识聊天，返回的 session 可用于重启接续。CLI 对应 --workspace、--source、--session。

已有任务用 task use 或 MCP use_task 按名称选择；新任务用 task add 或 MCP tasks(title=...) 创建。每项任务的 ~ 根下直接创建讨论主题。同父名称唯一，跨分支同名时用完整路径区分。CLI 将 "~/..." 加引号，避免 shell 展开。

## 记录与深入

note 按需要保存问题目的、用户已确定、助手建议、待讨论和下一步。状态为讨论中、已解决、暂放、已取消。部分结论已定时，保留仍开放的问题；缺少材料时注明缺口。

重要结论、分叉、转向或一轮讨论结束时更新。新问题建为当前节点的孩子，暂放旁枝记录返回条件。新增孩子和读取都保持位置；实际进入问题时用 focus 明确移动。

prompt 始终显示真实位置；target 和 node 表示本次操作对象。更新和移动携带读取到的 revision，发生冲突时合并 current 最新内容再提交。改名和移动后更新引用路径，工具保存的位置随内部身份跟随。

## 任务边界

跨任务查看、列孩子、查路径和搜索直接允许，保留当前绑定。修改其他任务时，按用户已表达的目标核对归属，确认本意确实跨任务后，在这一次请求显式提供 sudo。CLI 用 treecer sudo 前缀或 --sudo；MCP 写入工具用 sudo=true。

遇到 SUDO_REQUIRED 先核对当前任务、目标与候选路径，避免机械重试。目标意图仍不明确时再向用户澄清。一次覆写不固定到后续请求，task use / context use 才是明确换绑入口；focus 可以导航到其他任务，当前任务绑定保持原样。

## 回溯

context 一次提供祖先、当前正文和一层孩子，按需补读祖先内容。next_offset 非空时仍有后续页。

聊完一支，记录它解决了父问题的哪部分和剩余缺口，用 parent 查父位置，用 focus .. 返回，再选择未完成兄弟分支。暂放问题始终保留可接续线索；用户可改变顺序。重新开放时恢复讨论中，新决定替代旧建议时更新有效结论并保留必要理由。

交谈以实质问题为主。记录讨论沿用当前任务授权；代码、架构意图、部署和外部操作按各自任务授权推进。
